# my_restaurant.ai: Restaurant Sales Forecasting

![CI](https://github.com/c-dillon77-byte/my_restaurant.ai/actions/workflows/ci.yml/badge.svg)

A lightweight tool that forecasts **7-day, store-level net sales** from daily sales history, to give
restaurant managers a consistent starting point for labor scheduling, prep and inventory ordering.

It includes two forecasters:

| Script | Method | Status |
|---|---|---|
| `scripts/forecast_trimmed_mean.py` | **Same-weekday trimmed mean.** Takes the last 6 same weekdays, drops the highest and lowest, averages the rest, and applies an optional event multiplier. | Main model, tested in CI |
| `scripts/forecast_pytorch.py` | Small PyTorch network (store embedding + weekday + trend + the trimmed-mean baseline as a feature) | Experimental (see notes) |

> All sample data in this repo is **synthetic** (generated by `scripts/generate_synthetic_data.py`).
> It does not represent any real business.

## Why a trimmed mean?
Restaurant sales repeat by weekday (Fridays look like Fridays), but single days get distorted by events,
weather or a bad register export. Dropping the highest and lowest of the last six same weekdays keeps the
forecast stable and easy to explain to a manager, which matters more for adoption than a black-box model.

Worked example (last six Mondays): `2100, 2250, 2400, 2600, 1900, 2350` → drop `2600` and `1900` →
mean of the rest = **2275**. With a 10% event multiplier: 2275 × 1.10 = **2502.50**.

## Usage
```bash
# 1) (optional) regenerate the synthetic sample data
python scripts/generate_synthetic_data.py --output data/synthetic_sales.csv --weeks 20 --seed 42

# 2) forecast the next 7 days for every store
python scripts/forecast_trimmed_mean.py --input data/synthetic_sales.csv \
    --output output/forecast_example.csv --horizon 7 --multiplier 1.00
```

Options: `--horizon` (days, default 7), `--multiplier` (event/promo adjustment, default 1.00),
`--lookback` (same-weekday values used, default 6).

### Example output

```csv
2026-05-25,101,2341.01,2341.01,1.0,same_weekday_trimmed_mean
2026-05-26,101,2507.81,2507.81,1.0,same_weekday_trimmed_mean
2026-05-27,101,2528.24,2528.24,1.0,same_weekday_trimmed_mean
2026-05-28,101,2745.27,2745.27,1.0,same_weekday_trimmed_mean
2026-05-29,101,2880.27,2880.27,1.0,same_weekday_trimmed_mean
2026-05-30,101,3074.8,3074.8,1.0,same_weekday_trimmed_mean
2026-05-31,101,2038.55,2038.55,1.0,same_weekday_trimmed_mean
```

Edge cases: with fewer than 3 same-weekday values there's nothing to trim, so the plain average is
used (`method = same_weekday_mean_fallback`). Dates with no same-weekday history are skipped.
Duplicate store/date rows are collapsed (last one wins).

### Experimental PyTorch model
```bash
pip install -r requirements-ml.txt
python scripts/forecast_pytorch.py --input data/synthetic_sales.csv --output output/forecast_pytorch.csv \
    --epochs 1500 --lr 0.05
```
It needs at least 6 prior same-weekday values per store and 200+ usable training rows (the synthetic
file has enough). **Known limitation:** the sales target isn't scaled, so with the default settings
(`--epochs 200 --lr 0.001`) the model underfits badly (forecasts far below actual sales). On the
synthetic data, `--epochs 1500 --lr 0.05` produces forecasts close to the trimmed-mean baseline.
Scaling the target is the next planned improvement. Use the trimmed-mean model for real decisions.

## Testing
```bash
pip install -r requirements-dev.txt
ruff check .
pytest -q
```
The tests cover the trimmed-mean math (including the worked example above), weekday matching, the
multiplier, short-history fallback, input validation, duplicate handling and the data generator.
